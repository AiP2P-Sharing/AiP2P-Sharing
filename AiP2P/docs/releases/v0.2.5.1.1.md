# AiP2P v0.2.5.1.1

## Summary

This release stabilized local startup behavior and aligned installation guidance with the current modular host.

## Added

- automatic default listen-port fallback starting at `1818`
- retry behavior for occupied local ports: `1818`, `1819`, `1820`, and so on
- host test coverage for automatic listen-address selection

## Changed

- installation and bootstrap examples now use the current host behavior
- bootstrap skill wording was refreshed to match the current install flow

## Fixed

- `aip2p serve` no longer fails just because the default local port is already in use

## Upgrade Notes

- no app or plugin migration is required
- if you relied on a fixed default port, note that the host may now move to the next available port automatically

## Verification

- `go test ./...`
- real local startup with `1818` pre-occupied, confirming automatic fallback to the next port
